# 手机首页筛选修正

本轮修改首页原生片库 `VodTypeFragment`，不修改「公开片库」的 11 个来源或分类实现。

已核对原始调用链：服务端分类声明 → 首页标签 → `TYPE` → 原生目录；未发现标签顺序交换。实际筛选元数据使用 `type/year/area`，旧代码却把海外目录第三行写成 `language`，电视剧第三行写成 `start`。现在按实际元数据字段提交，全部值统一使用 UTF-8 编码，清空筛选发送空查询。

每次筛选建立独立的查询代次，立即清空旧卡片及页码。响应必须同时属于当前视图、目录、筛选、请求页，第一页完成前不能加载第二页；旧地区或销毁视图后的响应不再更新界面。分页底部判断使用从零开始的最后索引，按服务端 `totalpage` 和实际空页结束，不按 `videonum` 估算页数。失败解除加载状态，已完成的列表保留，可重试同一页。卡片沿用原适配器、原点击和焦点绑定，追加页不重设适配器，修正原共享列表重复计算插入范围的问题。

网络核验也发现上游数据问题：海外目录的「内地」结果及其影片详情都被服务端写为内地，客户端无法凭这些字段纠正真实国别。因此海外分类移除内地、大陆、中国大陆三个选项；其他原始地区名称不做别名替换。选择香港、台湾时查询电视剧目录对应的原始地区值，并使用该目录真实类型、年份选项，提示「香港电视剧」或「台湾电视剧」。电视剧目录香港第一页、第二页各 20 条，第 28 页 10 条，第 29 页为空；海外目录香港仅 2 条。台湾电视剧前两页及样本详情已经核验。此修正不声称上游所有地区标注均准确或片库齐全。

筛选结构在每个视图第一次成功获得有效字段时绑定一次；同一个请求的缓存、网络重复成功回调不会把当前香港、台湾、年份或排序选择重置。空或无效的结构不会阻止后续有效结构加载。

验证：51 项纯状态/查询/地区规则断言、84 项真实桥接代码的 ABI 形状替身断言、32 项实际 APK 内模型和 Volley/适配器方法签名检查；两份新 Java 已使用 Android API 35 编译。测试与证据仅写入本轮目录，不覆盖历史版本。设备布局、实际网络交互和电视端未在这组测试中执行。

执行：`python open-sources/tests/run_native_browse_137_tests.py`。

静态还原脚本：`open-sources/integrate_native_browse_1370.py`，仅从本轮 `before` 的两份原始 smali 生成冻结挂接，不修改请求签名、解密、账号或存储。
