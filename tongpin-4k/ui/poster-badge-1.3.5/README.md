# 海报空白角标与缺图状态修复

用户截图中的右上角白块来自 `mv_type_details_item.xml` 的 `video_score`：背景为白色，带最小尺寸；分类适配器把缺失评分填成两个空格，并使用字符串引用比较判断空值。搜索适配器也未更新可见性。

两处绑定现在共用 `i6/e.bindScore`，每次明确设置文本和可见性：null、空串、纯空白（包括 NBSP、全角空格）隐藏；有效文本显示，回收项从有评分到空评分、再到有评分不会残留旧状态。布局的初始状态为 gone，真实评分背景和样式保留。

两个主卡片绑定还共用 `posterUri`，只清理地址首尾 ASCII 空白、把空地址转为 null；保持原地址、协议、域名、标题和打开详情动作。Fresco 原有 String 重载会把 null 传入新 controller，因此空地址会重置回收项的旧图。

原缺图资源为透明底加白色播放图，在浅米底上几乎不可见。已有 `place_image_laye` 现复用 `tp_pressed` 底色和 `tp_mark` 标记；卡片与推荐项均配置了相同的 loading/failure 资源。fitXY 只让 layer-list 背景填满海报框，内部标记保留原固定50dp尺寸；已加载影片海报仍按原裁剪规则显示。

校验：

- `verify.py`：22项对实际 smali helper 的主机解释检查，覆盖 null、空白、Unicode 分隔空格、有效评分、复用状态及 URI 清理；另核对两个绑定钩子、布局 ID／控件类型及海报几何。
- `smali-assembly.json`：两个完整修改类经 Apktool 实际组装到 DEX，通过；生成的 proof APK 仅用于组装检查，不是生产安装包。
- `method-scope.json`：分类只修改 `e()` 并新增两个 helper，搜索只修改 `n()`；其余16个原方法保持字节文本不变。
- Impeccable 对卡片 XML 运行了限定目标的 regex 检测，未报告匹配项；原生渲染、对比度、字体放大和其他解析式规则未运行，不视为真机视觉验收。

未新增网络重试，也未换成其他影片的海报。上游地址缺失、404、网络失败或图片自身问题仍可能让真实海报不可用；本次提供清楚的缺图显示并修复空白地址绑定，不能据此宣称所有海报已恢复。

生产文件哈希位于 `source-freeze.json`。未修改播放器、选集、来源排序或签名材料；尚未进行设备验收。
