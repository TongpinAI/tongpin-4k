# MacCMS XML 接入

`maccms_xml` 使用相同 MacCMS 查询参数和既有 JSON 数据校验，只在响应传输层将标准 RSS 的 `class/ty`、`list/video`、`dl/dd` 转换为既有字段。`ty` 没有声明父级时保留扁平分类，不从编号猜测父子关系。年份、地区、集名、线路顺序和直接媒体地址保留来源实际值。XML 本身不授予更宽的媒体地址、分类或内容范围。

适配器采用 Android 自带 SAX 流式解析，在构造结果前限制深度64、元素25万、影片和分类各1000、线路32、输入及输出各8MiB UTF-8。原先手机1000集、电视10000集的下游限制不变。解析前拒绝 DOCTYPE 和 ENTITY 声明，外部实体解析器始终拒绝资源读取；不启用验证、XInclude 或外部样式处理。普通 XML 实体转义及 CDATA 保留标准含义。声明格式不符合受支持 RSS 结构时返回明确失败。

手机与电视适配器仅包名不同。两个 `CatalogApi` 仅扩展 MacCMS 类型判断、统一响应规范化入口与原有 ID/分类类型门控；电视的记录编解码、最高画质选择和10000集容量保留。

主机测试分别通过手机和电视实际 API 执行同一套42项断言，包括真实脱敏 XML 样本、类别过滤、媒体地址过滤、层级及容量边界、空线路标识、错误响应、XXE/实体声明和 UTF-8 字节边界。真正的本机 HTTP 夹具验证 `fetchCategories/fetchPage/fetchDetail` 的 XML 路由和参数；实体探测端点收到0次请求。Android API35 编译通过。未连接设备，夹具回放不代表第三方来源持续可用。原始播放 URL 没有纳入公开测试夹具。
