# 当前片源数据格式

本轮共享 API 支持 MacCMS JSON、MacCMS RSS XML、已确认的无 `code` 的 `class/list` JSON、静态 M3U 频道列表，以及原有 PeerTube。它们是直接数据格式适配，不执行 TVBox 配置中的脚本、Spider 或 JAR。

- `maccms`：保持原有成功码、类别、影片编号和直接媒体地址校验。
- `maccms_xml`：先经有界 SAX 转换为同一组数据字段，再执行原有校验；不从分类数字编号推测父级。
- `tvbox_json`：只有实际 `list` 数组存在、没有报告错误且没有失败状态时，才为缺失的成功码补 `1`；保留显式失败码，未加入 `code=200/data.list` 等其他结构。映射 `pageindex/pagesize/recordcount`；请求第二页及以后必须收到相符页码，避免把第一页重复展示成新一页。
- `m3u`：只处理实际 EXTINF 频道、分组、台标和 HTTP 媒体地址。直接静态文件使用本地分页、名称搜索与实际分组筛选，不追加 MacCMS 查询参数。同一实际 `tvg-id + 名称 + 分组` 的地址归为频道镜像；缺少稳定 ID 的条目还保留地址身份。来源名、频道名、分组和播放清晰度各自保留含义，频道不算电影剧集，未填写尺寸的流不标成4K。

M3U 输入8MiB、4万行、1万条 EXTINF、1000组、单频道32条线路受限；拒绝 URL 用户名密码、局域网和本机字面地址，以及需要自定义请求头或 DRM 插件的条目。公开 CDN 签名查询完整保留。仅打开频道详情时在工作线程检查频道域名，对同一域名去重，保留可解析为公开地址的线路；频道列表绑定不逐条做 DNS 查询。频道地址之后的媒体清单和分片由既有播放器处理，未增加代理或 DNS 固定转发层。

单个频道超过32条镜像时保留前32条候选，其余频道继续读取，镜像过多不会使整个来源失效。

来源配置上限从32扩大为128，33和128个合法来源全部保留，129个明确拒绝。电影、剧集的类别来自当前来源声明，不提供虚构的年份、地区服务端筛选。

`supportsSearch`默认开启，仅接受明确布尔值。来源声明`false`时，非空关键词在发起HTTP请求前明确失败；首页和换源界面改用实际分类及分页浏览，不发送不受支持的搜索，也不把这类电影片库当成直播。频道列表的本地搜索仍保留。

已确认的频道文件在媒体路径后附加`$LR•IPV4`或对应数字线路展示标记时，只按完整白名单语法去掉终端展示后缀。带查询字符串的地址保持原样，查询中的美元符号及签名值不截断；未知路径后缀不会被任意剥离。

实际 M3U 样本的本地解析得到380个支持的唯一频道和25个分组。联网审计只确认一个样本频道的媒体清单和 TS 片段可访问；该数量不表示全部频道持续可播或全部为4K。静态旧 JSON 快照中已经被实时片库覆盖的条目合并为别名，不额外计作一套可翻页片库。

主机验证入口：`run_unified_source_tests.py`、`run_xml_source_tests.py`、`run_m3u_source_tests.py`、`run_tvbox_json_tests.py`。各自报告位于本目录对应测试子目录。它们验证实际 Java 解析及策略、Android API 编译和本机 HTTP 夹具，不包含设备 UI 操作或全部第三方线路逐播。
