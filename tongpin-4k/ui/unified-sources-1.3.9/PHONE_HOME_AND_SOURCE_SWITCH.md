# 同频4K 手机首页与换源

首页由 `CatalogActivity` 统一展示当前配置里的全部片源：横向片源按钮、完整片源列表以及当前来源真实分类。分类 ID 不跨来源沿用；切换来源后重置分类并重新读取声明。入口名称为“同频4K”，不再需要先进入另一套“公开片库”。启动清单和旧播放器的桥接由本轮主集成负责。

来源显式声明不支持关键词搜索时，首页清空并禁用搜索，保留实际分类和翻页；播放器换源同样显示分类浏览与实际分页，不把随机返回的影片当搜索命中。该能力与直播类型分开，不能搜索的电影片库仍按电影、剧集和实际选集播放。

播放器“换源”和“更多→换源”使用实际配置的同一份片源列表。流程为选择片源、搜索当前片名、确认影片、读取实际详情和线路，再选择实际选集。当前来源自己的其他线路也可以直接读取。同名候选不会自动认作同一作品；只有严格作品身份与唯一选集身份同时成立，用户确认后才沿用当前进度。无法确认时显示实际选集列表，使用目标选集自己的断点。不会把原线路的第 N 个按钮直接转成新线路第 N 个按钮。

作品身份保留年份和来源分类，拒绝已知年份、类型冲突；缺少结构化元数据时只接受足够长、内容有差异度且包含关系明确的简介，重复“暂无简介”等套话不能确立作品身份。选集解析保留季号，拒绝重复集号、预告、彩蛋、陪看、上下篇、日期和画质标签。影片名称中的季号不删除。新旧队列均可读取，新队列在应用私有缓存中保存提供方和影片元数据，Intent 继续只传短令牌。

“我的”只包含观看历史和收藏。新观看记录和收藏使用本地有界存储，无需登录；历史保存真实片源、线路和集名，重读当前详情后仅在唯一匹配时继续播放，否则展示选集。旧原生历史和收藏的真实入口保留在对应列表里，原有数据库记录不改写。旧记录只有选集序号，无法确认新片源中的实际集号；首次进入新片库时需要确认实际片源、影片和选集，不猜测旧序号，也不自动套用旧进度。完成播放后会建立新的观看记录，后续从新观看记录可以断点续播。原生历史 Intent 的 `type=2` 为观看历史、`type=1` 为收藏，按现有字节码核对。

换源候选查询在有界单工作线程中执行；成功播放不会周期性查询其他来源。新队列写入完成后才替换当前播放，后台、销毁、切集或播放代次变化会丢弃过期结果。确认切换时捕获当前实际进度和暂停状态；保留固定倍速。原有清晰度短时显示、2×长按及向右拖动3×、真实字幕、正倒序选集、上一集/下一集、自动连播、断点续播、解码和全屏控制继续使用现有实现。

M3U 内容明确标为直播频道，使用来源真实分组和频道名，清晰度等待解码后实测。直播不保存、恢复或跨源套用进度，禁用时间跳转及临时倍速，按实时1×播放；返回电影剧集后保留此前选择的固定倍速。已打开的旧播放器换源经统一入口打开新播放器，返回时可能回到原播放器；取消换源会返回原播放。旧历史列表的影片点击直接使用新的确认流程，不要求先运行旧启动页。

验证：`open-sources/tests/run_unified_source_tests.py` 编译完整手机 Java 源码，并运行实际匹配、元数据序列化、队列、存储边界与原有播放策略测试。输出位于本目录 `tests/verification.json`。这些是主机测试与 Android API 编译；未连接手机、未构造真实 Activity、未声称完成设备 UI 测试，也不保证任意第三方来源持续在线。
