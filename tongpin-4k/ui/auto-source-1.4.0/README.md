# 手机 1.4.0：自动为当前集选源

从统一首页、选集和旧记录确认后进入新播放器，先播放当前线路；后台做一次有上限的同作品、同一实际集号比较，再提交最终更好的可用结果。4K 优先，同档优先正片更新覆盖，再比较1080p等可用清晰度。源标签或HLS声明分辨率不当作实际解码分辨率；播放角落分辨率仍只显示3秒。只有来源本身明确提供的干净版本提示参与偏好，不承诺识别或消除画面内角标。

自动提交重新核对作品、唯一实际集号和最新解码尺寸，使用提交当时进度、固定倍速和播放/暂停意图。拖动、长按临时加速、切换和后台时不提交；待提交结果15秒过期。用户明确点画质或换源后，本集保持手动选择。切到新集重新允许一次比较；真实加载错误最多再做一次排除故障URL的恢复。拖动/进度操作附近错误只保留错误提示，不据此把线路判坏。

直播不参与选源或VOD进度恢复。旧隐藏原生播放器保留原有功能；旧历史记录确认实际源/集后进入统一播放器，即使用此功能。无设备连接，本轮验证为完整Java编译、纯状态/实际队列策略、实际DEX ABI与包签名/资源门禁；不宣称真机画面、网速或全部远端线路始终可用。

`phone-source-freeze.json`只覆盖手机调用者；共享的AutoSourcePolicy/AutoSourceSelector另有跨端源哈希及网络安全测试。已发布139目录、原生smali、28项源注册表保持原样。

构建使用 `open-sources/staging-1.4.0-r2/own-classes.dex`。未发布的r1尝试在发现原生准备回调时序后停止，未产出成品；其报告保留在 `aborted-r1/`。r2从实际GSY smali验证“state1先回调i，再执行原生startAfterPrepared”，使用本代prepared标志加单次View.post；已准备的缓冲state3只开始一次后台比较，提交仍须稳定状态，初次准备仅投递一次，不增加重试计时器；待提交结果仍按前文15秒窗口等待稳定。证据见 `native-prepared-order.json`。
