## 构建与维护

既有实现位于 `decoded/`：Android 资源 XML 与 smali；新增公开片库源码位于 `open-sources/src/`，包含三份自有 Java 文件。当前仍不是完整的 Android Studio／Gradle 重写工程。自定义图标源文件在 `assets/tongpin4k-icon.svg`，设计记录在 `DESIGN.md`。

在本机运行：

```powershell
python .\build_tongpin.py
```

脚本使用相邻 `kanke-noads/tools` 中已校验的 Apktool、Android Build Tools 和本机 JBR。Windows 资源编译通过 `D:\DevTools\tmp\tongpin4k-build` 的目录 junction 使用 ASCII 路径；Apktool 内置兼容 aapt2 用于重编原包的保留资源名，官方 SDK 工具用于最终检查、16KB 对齐和签名。

如果修改新片库 Java 源码，应先按 `open-sources/toolchain/README.md` 的流程重新编译、生成并合入自有 smali，刷新本轮集成记录，再构建整包。编译桩和主机测试用 org.json 不进入 APK；1.1.3采用新编译的 `staging-1.1.3-r1`，五份源码及65个自有smali哈希记录于 `open-sources/integration/1.1.3.json`。

1.1.3/code1103已完成整包构建。后续重新编译必须选择尚不存在的新stage目录，例如 `python .\open-sources\toolchain\compile_java_to_smali.py .\open-sources\src .\open-sources\staging-1.1.3-r2`，并为新发布版本刷新集成记录、版本配置及旧代码精确合同。本轮集成记录的 `additional_allowed_apk_entries` 限定三个旧集数布局变化。整包以1.1.2作ZIP差异基线，保留原四DEX和原非自有类；自有类清单按新stage核对，类数不固定58。签名候选通过检查后才晋升为独立 `output/tongpin-4k-1.1.3.apk`；已有release不会覆盖。最终DEX的65个自有类及5个旧播放器类另经定向反汇编，736条实际调用ABI检查通过，证据见 `verification/1.1.3/`。

签名材料保存在本机项目 `signing/` 目录，不在 APK 内。请妥善保留，勿将私钥或密码文件公开；丢失后将无法以同一签名原位更新此客户端。
